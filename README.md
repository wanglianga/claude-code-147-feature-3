# 云溪山居 · 乡村民宿旺季运营平台

面向乡村民宿旺季（节假日）的一体化运营平台：统一 **官网 / 小程序 / OTA / 电话** 四渠道的房态、价格、入住人数、宠物规则、儿童加床、早餐份数、押金与发票要求；把 **订单 → 保洁 → 布草 → 维修 → 早餐 → 事件 → 差评归因复盘 → 店主补救 → 客人改评观察 → 结算** 放进同一条住宿链路；旺季结束后按渠道/房型/服务环节复盘利润与**渠道真实获客成本（佣金+已被客人接受的补救成本）**，据超卖、布草延迟、早餐投诉、补偿成本、补救是否被接受/差评是否被修改，自动调整下一轮节假日的可售房量并给出旺季排班建议。

## 技术栈

- 前端：React 18 + Vite + Ant Design 5 + ECharts
- 后端：NestJS 10 + TypeORM（含 Swagger 文档 `/api/docs`）
- 数据库：PostgreSQL（开发用 15 验证，Compose 用 16）

## 一键启动（Docker Compose）

```bash
docker compose up --build
```

- 前端：http://localhost:8080
- 后端 API：http://localhost:3000/api （Swagger 文档：http://localhost:3000/api/docs）
- 首次启动自动建表并写入 **2026 国庆旺季（10-01~10-08，"今天"为 10-03）** 演示数据：12 间房、4 渠道、20 张订单、保洁/布草/维修/早餐记录、除湿设备台账、8 类履约事件、6 条评价与完整补救改评故事线。

## 本地开发

```bash
# 1. 数据库（任一方式）
docker compose up -d db                                  # 用 Compose 起 Postgres(5432)
# 或使用本机已有 PostgreSQL，创建 homestay 库后通过 DATABASE_URL 指向它

# 2. 后端（首次启动自动建表+种子数据）
cd server && npm install
DATABASE_URL=postgres://homestay:homestay123@localhost:5432/homestay npm run start:dev

# 3. 前端（Vite 代理 /api → localhost:3000）
cd web && npm install && npm run dev                    # http://localhost:5173
```

## 演示动线（种子数据已埋好完整故事线）

1. **经营看板**：入住率/ADR/RevPAR、渠道收入分布、履约事件分布、差评归因四象限（硬件/服务/超卖/餐食）。
2. **房态日历**：房间×日期占用与价格；下方库存表可见 10-01 庭院双床房、10-04 山景大床房两处**超卖**红色告警。
3. **订单管理**：新建订单会统一校验宠物/加床/人数规则与库存（OTA 可强制下单并触发超卖事件）；订单详情抽屉含 **链路事件 / 保洁 / 评价补偿 / 结算明细** 五个页签。可现场操作：入住 → 临时加人（早餐费自动重算）→ 延迟退房（自动生成事件+保洁任务）。
4. **保洁与布草**：「智能排班」按下一单入住时间、脏污程度、维修冲突、布草库存自动派单（301 房有空调维修告警）；完成打扫扣减布草；送洗签收超时 2 小时自动记布草延迟事件。
5. **早餐备餐**：按在住人数与忌口（不吃辣/素食/海鲜过敏）自动汇总需求；确认备餐量不足即生成早餐供应不足事件。
6. **事件与差评**：差评（≤3 分）自动进入链路并打上归因标签（早餐少/房间潮湿/入住等待久/布草延迟/保洁完成晚）。
7. **差评复盘与补救**（新页面"差评复盘与补救"）：以 OTA 客人**林女士**一单为完整故事线——同一复盘页并列展示 **早餐备餐（10-03 需求17份实备12份）、除湿设备（DH-01 夜间异常、湿度85%）、保洁完成时间（15:10 才打扫完，超14:00截止线70分钟）、布草延迟、管家沟通记录（7条微信/当面/电话时间线）**，并汇总成一条住宿链路统一时间线。店主在页面对差评四选一：**退款 / 补偿券（自动生券码）/ 电话道歉 / 不予补偿**；随后登记**客人是否接受**（拒绝则差评事件退回待处理、补偿作废）；补救完成后平台持续**观察客人是否修改差评**（登记改评 2→4 / 观察结束未改评）。种子还埋了两条闭环：王先生一家补偿券被接受后改评、吴女士退款被接受后改评；刘女士电话道歉被拒后改退款 80 元方被接受。
8. **渠道真实获客成本与评分恢复**：旺季复盘新增分渠道表，真实获客成本 = 渠道佣金 + **已被客人接受**的补救成本（待回应/被拒绝/作废的补偿不计入）；同时给出各渠道差评均分原始→当前、改评/观察中/未改评数与补救接受率——接受率低、评分未恢复的渠道压缩旺季配额。
9. **下次旺季排班建议**：按本次每日在住/退房压力、早餐不足、除湿异常、布草延迟给出每日保洁人数、厨房帮工与备餐量、除湿巡检次数、布草安全库存；**客人未接受补救或未改评的离店日自动加排 1 名保洁并提示管家优先回访，已接受且改评的按常规排班**。
10. **结算中心**：每笔订单的房费、加床、早餐、宠物费、渠道佣金（OTA 15%）、赔付补偿（仅计已接受补救）、押金扣留/退还、净收入逐行列清。
11. **旺季复盘**：分渠道/分房型利润表、服务环节收入 vs 成本、问题自动归类（价格策略问题/履约能力问题/个别客诉）；最下方给出下一轮节假日各房型**建议可售房量**，调整因子在超卖/布草/早餐/补偿之外新增"补救未被接受、差评未改评"，选择日期区间后「应用到下一轮节假日」即写入库存。

## 验证方式（实际执行过的验证）

本仓库交付前在 Linux + PostgreSQL 15 + Node 22 环境实际执行：

```bash
# 后端编译
cd server && npx tsc -p tsconfig.build.json

# 端到端 API 验证（97 项断言全部通过）
python3 scripts/verify.py

# 前端构建
cd web && npm run build
```

`scripts/verify.py` 覆盖：登录鉴权、禁宠/加床/人数规则拒绝、库存不足 409、OTA 强制下单触发超卖事件、临时加人费用重算、延迟退房事件、退房生成保洁任务、智能排班（含维修冲突告警）、保洁完成扣减布草、布草延迟事件、早餐需求汇总与不足事件、除湿设备巡检与管家沟通追加、**差评复盘页五类证据聚合与统一时间线、四种补救决策及金额校验、客人接受/拒绝（含拒绝后改退款、重新决策作废旧单并作废补偿券）、不予补偿闭环、改评 2→4 留档与观察结束、待回应补偿不计入真实 CAC/接受后计入、渠道评分恢复与补救接受率、旺季排班（布草缓冲/加厨房/补救联动）、调价新增"未接受/未改评"因子**，以及结算净额勾稽、OTA 15% 佣金校验、复盘三分类、调价建议与库存应用。

前端通过 `npm run build` 构建，并以 `vite preview`（4173 端口，代理 `/api`）验证页面、静态资源与 `/api` 代理连通（登录接口 201）。

### 本地连库说明

默认连接 `postgres://homestay:homestay123@localhost:5432/homestay`，可用 `DATABASE_URL` 覆盖；首次启动对空库自动建表（`synchronize: true`）并写入种子数据。重置演示数据：停服后清空/重建库再启动即可。
